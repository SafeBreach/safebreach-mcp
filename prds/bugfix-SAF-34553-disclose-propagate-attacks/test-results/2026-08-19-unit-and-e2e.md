(`SELECT count(*) FROM move WHERE tags ? 'ALM'` → 111) via a completely separate path — the
discriminator agrees with the database.

The reporter's own figure reproduces: for the Credential Access tactic, the live run reports
**45 Propagate**, exactly the 45 quoted in SAF-34553. (Validate differs — 136 vs the reported 108 —
because the console carries more content than the reporter's did.)

## Defect found BY the e2e run, not by the unit suite

The disclosure hint rendered as `...page_number=1 111 Propagate (ALM) attacks...` — the paginator's
hint carries no trailing punctuation, so concatenation produced a run-together sentence in the exact
text an LLM is meant to act on. T-17 asserted only that both fragments were *present*, so it passed
on broken output. Fixed in `c900bf4`; T-17 strengthened to assert the boundary. This is the clearest
argument in this ticket against shipping on unit tests alone.

  against 121. Only Phase 8 closed the gap.
- DB cross-checks in the original section used the `move` table (9,605 rows). The KB API serves

  exactly and `status: "draft" | "published"` is a documented configuration-API enum, but the specific
  UI/endpoint code performing the exclusion was not located.
